# Chunking Implementation Plan

## Goal

Implement a Markdown chunking pipeline for the RAG ingestion system.

The chunker will:

1. Read parsed Markdown files from `data/processed/`
2. Split them into retrieval-ready chunks
3. Attach standardized metadata
4. Save the result as `.jsonl` files under `data/chunks/`

---

# Pipeline Position

```text
Crawler
    ↓
data/raw/*.pdf (hashed filename)
    ↓
Parser
    ↓
data/processed/*.md (same hashed stem)
    ↓
Chunker
    ↓
data/chunks/*.jsonl
    ↓
Embedder
    ↓
Qdrant
```

---

# Existing Manifest Format (inside data/cache/manifest.json)

The project already uses the following manifest schema, and **it should remain unchanged**.

Example:

```json
{
  "site_name": "curriculum",
  "file_name": "Chuong trinh dao tao 2016,2017.pdf",
  "file_path": "raw\\\\curriculum\\\\d21e986671e6fbec.pdf",
  "file_size": 3076087,
  "file_hash": "d21e986671e6fbec",
  "created_at": "2026-07-19T16:06:42Z"
}
```

---

# Manifest Mapping Rules

The chunker must use the manifest to map hashed markdown files back to the original downloaded documents.

## Mapping Table

| Manifest Field | Meaning in Chunking        |
| -------------- | -------------------------- |
| `site_name`    | `source_type`              |
| `file_name`    | `original_filename`        |
| `file_path`    | Original raw file location |
| `file_hash`    | `document_id`              |
| `created_at`   | Download timestamp         |

## Example

Processed file:

```text
data/processed/curriculum/d21e986671e6fbec.md
```

The file stem is:

```text
d21e986671e6fbec
```

The chunker should look up the manifest entry where:

```python
item["file_hash"] == "d21e986671e6fbec"
```

and obtain:

```python
source_type = item["site_name"]
original_filename = item["file_name"]
document_id = item["file_hash"]
```

# Important: Title Extraction

**Do not use `file_name` to generate chunk IDs or document titles.**

The original filename is preserved for:

* debugging
* traceability
* future citation enrichment

The semantic title must be extracted from the Markdown content.

# Required Chunk Schema

```json
{
  "document_id": "d21e986671e6fbec",
  "chunk_id": "curriculum_chuong_trinh_dao_tao_2016_2017_f3a2_0000",
  "source_type": "curriculum",
  "original_filename": "Chuong trinh dao tao 2016,2017.pdf",
  "document_path": "curriculum/d21e986671e6fbec.md",
  "document_title": "Chương trình đào tạo 2016, 2017",
  "chunk_index": 0,
  "content": "The training program requires 120 credits...",
  "content_hash": "8f3a9c1d..."
}
```

---

# Field Definitions

| Field               | Purpose                                                              |
| ------------------- | -------------------------------------------------------------------- |
| `document_id`       | Stable identifier from `file_hash`                                   |
| `chunk_id`          | Stable unique chunk identifier                                       |
| `source_type`       | curriculum / information / announcement                              |
| `original_filename` | Original downloaded filename from manifest                           |
| `document_path`     | Relative path of the source markdown file                            |
| `document_title`    | Human-readable title extracted from markdown                         |
| `chunk_index`       | Order of the chunk within the document                               |
| `content`           | Actual chunk text used for embedding and retrieval                   |
| `content_hash`      | SHA256 hash of `content` for deduplication and incremental embedding |

# Document Title

The chunker must use the original filename from the manifest as the document title.

Example manifest entry:

```json
{
  "file_name": "Chuong trinh dao tao 2016,2017.pdf"
}
```

The resulting title is the filename **without the extension**:

```text
Chuong trinh dao tao 2016,2017
```

Implementation:

```python
from pathlib import Path

document_title = Path(manifest_item["file_name"]).stem
```

This approach is intentionally simple and deterministic:

- it does not depend on OCR quality,
- it works for all document types,
- it is always available from the manifest,
- and it keeps the chunking stage lightweight.

The manifest remains the canonical source of document metadata, while the chunker focuses only on splitting content and generating chunk objects.

# Chunking Rules (only used for referencing)

## Chunk Size

* Target: **1000 characters**
* Acceptable range: **800–1200 characters**

## Overlap

* **150 characters** between consecutive chunks.

---

# Splitting Strategy

Apply in this order.

## 1. Split by Markdown Headings

Prefer boundaries at:

```markdown
# Heading
## Heading
### Heading
```

Keep headings with their associated content.

## 2. Split by Paragraphs

If a section is too large, split on blank lines (`\\n\\n`).

## 3. Final Fallback

If a paragraph still exceeds the limit, split by character count while preserving overlap.

---

## Chunk ID Strategy

Use the following deterministic format:

```text
{document_id}_{chunk_index:04d}
```

Example:

```text
d21e986671e6fbec_0000
d21e986671e6fbec_0001
d21e986671e6fbec_0002
```

This strategy is recommended because:

- `document_id` is already globally unique (from `file_hash` in the manifest).
- `chunk_index` preserves the order of chunks within the document.
- IDs remain stable across re-runs as long as the chunking configuration does not change.
- The format is short, deterministic, and ideal for Qdrant point IDs and incremental upserts.

---

# Incremental Logic

The chunker must skip files that are already up to date.

## Skip Condition

Skip when:

* `force == False`
* output `.jsonl` exists
* output modification time is newer than or equal to the source `.md` file

Pseudo-code:

```python
if (
    not force
    and output_path.exists()
    and output_path.stat().st_mtime >= input_path.stat().st_mtime
):
    logger.info(f"Skipping chunking: {input_path.name}")
    return
```

# Integration with run_ingestion.py

Chunking should be executed immediately after parsing.

Example:

```python
async def main():
    logger.info("Starting ingestion engine...")

    parser = LlamaParser()
    await parser.parse_directory()

    chunker = Chunker()
    await chunker.chunk_directory()

    logger.info("Ingestion engine run completed.")
```

This ensures the pipeline always runs:

```text
Parse → Chunk
```

in a single ingestion command.

---

# Success Criteria

Running:

```bash
python -m pipeline.run_ingestion
```

should:

1. Parse new or updated raw documents into markdown
2. Skip already parsed markdown files
3. Generate chunk `.jsonl` files under `data/chunks/`
4. Skip already chunked markdown files
5. Produce deterministic chunk IDs
6. Include all required metadata fields
7. Correctly map `document_id` back to the original filename using the manifest
